# CLI UX 규칙 (mn4-librarian 전용)

이 프로젝트의 "UI"는 터미널 출력이다. UI/UX 고도화 작업 시 아래 기준을
따른다.

## 플래그 네이밍

- 파괴적 동작은 전부 `--apply` (기본값 dry-run) — 새 명령도 동일한 이름을
  쓴다. `--confirm`, `--yes`, `--force` 같은 동의어를 새로 만들지 않는다.
- 배치 크기/동시성은 `--limit N`, `--workers N` 패턴을 따른다.
- 새 boolean 플래그는 kebab-case, 기본값 false, 이름만 보고 켰을 때 무엇이
  달라지는지 알 수 있어야 한다 (`--allow-new-major`가 좋은 예).

## Dry-run 메시지

- dry-run 모드에서는 출력 맨 앞이나 끝에 "실제로 아무것도 바뀌지 않았다"는
  사실이 명확히 보여야 한다. `--apply`를 안 붙였을 때 사용자가 "진짜
  적용됐나?" 헷갈리지 않는 것이 최우선이다.

## 배치 작업 진행 상황

- `ingest`/`migrate`/`fill-years`처럼 ThreadPoolExecutor로 여러 건을
  처리하는 명령은 건별 성공/실패/스킵을 구분해서 출력한다. "3/50 처리 중"
  같은 뭉뚱그린 카운터만 보여주고 실패 원인을 숨기지 않는다.
- 10건마다 체크포인트를 저장하는 기존 관례(migrate.py)를 새 배치 명령에도
  유지한다 — 중간에 죽어도 결과가 남아야 한다.

## 에러 메시지

- 배치 처리 중 개별 항목이 실패해도 전체를 죽이지 않는다(pdf_extract.py의
  넓은 예외 처리 관례를 따른다). 단, 실패한 항목은 어떤 파일/책 때문에 왜
  실패했는지 반드시 출력에 남긴다 — "3건 실패"만 찍고 끝내지 않는다.

## 검토 큐 JSON (tags review-files / apply-file-actions)

- 이 JSON은 사람이 직접 열어서 고치는 파일이다. 필드를 추가할 때는 항상
  이전 버전 JSON도 그대로 읽을 수 있어야 한다(신규 필드는 optional + 안전한
  기본값). 필드명을 바꾸거나 제거하는 것은 breaking change로 취급하고
  커밋 메시지에 명시한다.
