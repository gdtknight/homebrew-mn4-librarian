# 에러 처리 & 안정성 규칙 (mn4-librarian 전용)

"에러가 나면 죽는다"를 기본값으로 두지 않는다. 아래 기준으로 예외를
처리한다.

## 최상위 예외 경계

- `cli.py`의 각 진입점(one-shot `main()`과 REPL 루프)은 명령 실행부를
  하나의 예외 경계로 감싼다. 처리되지 않은 예외가 파이썬 기본 트레이스백
  형태로 사용자에게 그대로 노출되는 것을 기본 동작으로 두지 않는다.
- 예상 가능한 도메인 에러(설정 없음, DB 손상, MN4 실행 중, PDF 파싱 실패 등)는
  한 줄짜리 한국어 메시지로 `stderr`에 출력하고, one-shot 모드는 0이 아닌
  종료 코드로 끝내고 REPL 모드는 프롬프트로 돌아온다.
- 예상하지 못한 예외도 동일하게 잡되, 기본은 요약 메시지만 보여주고 전체
  트레이스백은 `MN4_LIBRARIAN_DEBUG=1` 환경변수(또는 `--debug` 플래그)가
  설정된 경우에만 출력한다 — 디버깅 정보를 완전히 없애지 않고, 평소 출력만
  깨끗하게 유지한다.
- `KeyboardInterrupt`는 일반 에러와 다르게 취급한다. 배치 작업 중 Ctrl-C는
  "N건 처리 완료, M건 중단"을 명확히 출력하고 안전하게 멈춘다(진행 중이던
  트랜잭션은 safety.py의 롤백 경로를 그대로 탄다) — 일반 예외 메시지 포맷으로
  뭉뚱그리지 않는다.

## REPL 세션은 명령 하나의 실패로 죽지 않는다

- REPL 루프 안에서 한 명령이 예외를 던져도 세션은 종료되지 않는다. 에러
  메시지를 출력한 뒤 다음 입력을 계속 받는다(`interactive-mode.md` 참고).
  세션을 끝내는 것은 `exit`/`quit`/EOF뿐이다.
- one-shot 모드(`mn4-librarian ingest` 등 인자와 함께 바로 실행)는 기존처럼
  실행 후 프로세스가 끝나는 것이 정상이다 — "안 죽는다"는 REPL 세션에
  한정된 규칙이지, one-shot 명령이 항상 0으로 종료해야 한다는 뜻이 아니다.

## 배치 처리 중 개별 실패는 전체를 막지 않는다

- `ingest`/`migrate`/`fill-years`처럼 여러 건을 순회하는 명령은 한 건의
  실패(PDF 파싱 실패, LLM 호출 실패, 개별 파일 이동 실패)가 나머지 건 처리를
  막지 않아야 한다 — `pdf_extract.py`의 넓은 예외 처리 관례를 파이프라인
  전 단계(추출 → LLM 분류 → 파일명 조립 → 이동)로 일관되게 확장한다.
- 실패한 항목은 어떤 파일 때문에 왜 실패했는지 결과 요약에 남긴다(`ui-ux.md`
  의 에러 메시지 규칙 참고). 10건마다 체크포인트를 저장하는 기존 관례를
  유지해 중간에 죽어도 이미 처리된 결과는 남는다.

## DB 쓰기 경로는 예외 경계와 무관하게 안전해야 한다

- `safety.py`의 트랜잭션은 이 상위 예외 경계와 별개로 동작한다. REPL/CLI의
  "에러 나도 안 죽는다"는 처리는 safety.py의 롤백·백업 흐름을 대체하거나
  건너뛰지 않는다 — 예외를 상위에서 잡아 메시지만 보여줄 뿐, DB 트랜잭션
  자체의 커밋/롤백 판단은 항상 safety.py 안에서 끝나 있어야 한다.
